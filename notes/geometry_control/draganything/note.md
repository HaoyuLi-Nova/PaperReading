# DragAnything 论文精读笔记

**DragAnything: Motion Control for Anything using Entity Representation，ECCV 2024**  
[论文 arXiv v3](https://arxiv.org/html/2403.07420v3) · [会议版](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/03277.pdf) · [项目页](https://weijiawu.github.io/draganything_page/) · [官方代码](https://github.com/showlab/DragAnything)

## 1. 科学问题与解决方案

**仅给一条二维拖拽轨迹，模型可能选错运动对象，也可能只移动目标的一小块。** 用户提供首帧、目标区域与二维锚点轨迹，模型输出 RGB 视频。图 3 中，拖动云朵上的一个点，DragNUWA 生成的是类似相机移动的画面变化。在鱼和海鸥的样例里，拖拽点附近的像素运动更强，实体出现局部变形。作者据此提出两个问题：模型如何知道用户选中了哪个实体，以及如何让控制作用到实体的整体运动。[论文 §3.1、图 3](https://arxiv.org/html/2403.07420v3#S3.SS1)

**DragAnything 给每条轨迹绑定首帧的实体特征。** 从图像扩散模型提取首帧中间特征，在目标掩码内做平均，得到固定的实体向量。沿用户轨迹逐帧移动这个向量的写入位置，并在同一位置生成二维高斯图。实体图给模型提供所选区域的语义与外观线索，高斯图提供运动锚点的位置与邻域。再经 ControlNet 式分支将两者注入视频去噪过程。[论文 §3.2–3.4、图 4–5](https://arxiv.org/html/2403.07420v3#S3.SS2)

**作者的机制解释是，同一个实体跨帧保留一致的特征，结合逐帧位置约束，更容易让模型把拖拽分配给正确的目标。** 这给出两个不同的验证问题：锚点是否更贴近轨迹，整个实体是否一起运动。表 2 的消融主要回答前者，图 3 和图 7 给出了后者的样例证据。[论文 §4.2–4.3](https://arxiv.org/html/2403.07420v3#S4.SS2)

## 2. 数据集构建

论文使用公开全景视频分割数据集 **VIPSeg**，训练划分用于学习，验证划分用于评测。VIPSeg 原论文报告全库含 **3,536 段视频、84,750 帧** 带像素级全景标注的图像。DragAnything 未报告筛选后实际使用的训练片段数、原始帧率及片段时长。论文给出的训练设置为 **25 帧、320×576 像素（高×宽）**。仓库还列出 YouTube-VOS 的准备和训练入口，正文的实验设置明确描述了 VIPSeg。[DragAnything §4.1](https://arxiv.org/html/2403.07420v3#S4.SS1) · [VIPSeg 原论文](https://openaccess.thecvf.com/content/CVPR2022/html/Miao_Large-Scale_Video_Panoptic_Segmentation_in_the_Wild_A_Benchmark_CVPR_2022_paper.html) · [仓库说明](https://github.com/showlab/DragAnything#dataset-prepare)

以一朵云和三帧为**说明用示例**。设首帧掩码的内接圆半径为 20 像素，锚点依次为 $(100,80)$、$(120,80)$、$(140,80)$。坐标以像素为单位，$x$ 向右、$y$ 向下。用 $i$ 表示帧索引，$t$ 表示扩散时间步。

| 步骤 | 从原始样本到条件或监督 |
| --- | --- |
| 1. 定义实体并跟踪锚点 | 从首帧分割标注提取云朵掩码 $M_1[H,W]$，用内接圆求中心和半径 $r$。Co-Tracker 在真实视频中跟踪中心，得到 $P[T,2]$。掩码是数据集标注，轨迹是跟踪器估计值。 |
| 2. 提取实体向量 | 将首帧编码并在一个扩散时间步加噪，由预训练图像扩散 U-Net 提取中间特征。掩码对齐到特征网格后，在覆盖位置取均值，得到 $e[C_e]$。公开示例采用 ChilloutMix 的扩散图像特征（DIFT），取第 4 个上采样块的特征，默认扩散时间步索引为 261，并对 8 个采样副本求平均。这些属于演示代码设置。 |
| 3. 生成实体图 | 对每帧初始化零图。在以该帧锚点 $P_i$ 为圆心、半径为 $r$ 的区域内写入同一个 $e$，叠成 $\hat E[T,H,W,C_e]$。三帧中向量不变，圆心依次移到三个指定位置。区域内每个像素具体怎样运动，由视频模型生成。 |
| 4. 生成二维高斯图 | 每帧在同一锚点画一块二维高斯响应，中心最强，向外衰减，空间范围随掩码导出的半径变化。逻辑形状为 $G[T,H,W]$，公开演示将这张灰度图复制成 3 通道。 |
| 5. 保留损失掩码 | 训练时保留逐帧实体掩码 $M[T,H,W]$，用于选择计入去噪损失的位置。这与仅用于提取实体向量的首帧掩码，以及由轨迹构造的两张条件图各司其职。 |

$T$ 为帧数，$H,W$ 为图高、宽，$C_e$ 为实体图通道数。公开单视频演示把绘制半径限制在 50 像素以内，将标准差为 **40 个模板像素**的圆形截断高斯模板缩放并贴到画面，边界处做裁剪。缩放后有效范围随目标区域大小改变，重叠处可能由后写入的实体覆盖。论文未完整说明训练时的遮挡、出界和重叠处理策略。[论文 §3.3–3.4、图 5](https://arxiv.org/html/2403.07420v3#S3.SS3) · [高斯模板](https://github.com/showlab/DragAnything/blob/main/demo.py#L188) · [演示条件构造](https://github.com/showlab/DragAnything/blob/main/demo.py#L290) · [DIFT 实现](https://github.com/showlab/DragAnything/blob/main/utils/dift_util.py#L197)

## 3. 模型架构

**两路首帧条件沿用 SVD 接口。** 基座是图像到视频的 Stable Video Diffusion（SVD），论文未报告 DragAnything 的总参数量或可训练参数量。VAE 的空间下采样倍率为 8。在三帧示例中，若图像为 320×576 像素，带噪视频潜变量形状为 $[B,3,4,40,72]$。首帧加噪增强后经 VAE 编码为 4 通道，沿帧维复制，再与视频潜变量**沿通道维**拼接成 $[B,3,8,40,72]$。$B$ 表示批大小，省略分类器无关引导引起的批维复制。另一路是 CLIP 图像编码器生成的全局特征 $[B,1,1024]$，交叉注意力的查询（Q）来自视频特征，键和值（K、V）由首帧全局特征投影得到。示例中的 3 帧用于说明张量流。[论文 §3.2](https://arxiv.org/html/2403.07420v3#S3.SS2) · [SVD 配置](https://huggingface.co/stabilityai/stable-video-diffusion-img2vid/blob/main/unet/config.json) · [公开推理管线](https://github.com/showlab/DragAnything/blob/main/pipeline/pipeline_svd_DragAnything.py#L450)

**实体图与高斯图在控制分支内部相加，再通过残差进入主网络。** 公开代码用两路逐帧卷积编码条件，各经 3 次步长为 2 的下采样，在示例分辨率下得到 $[B\times T,320,40,72]$。两路先相加，再加到控制分支**输入卷积之后**的同形状激活。论文式（2）概括为条件与带噪潜变量相加，公开代码中的实际加法发生在输入投影之后。控制分支经过时空下采样块和中间块，由零初始化卷积投影出多尺度残差，分别加到 SVD U-Net 的跳跃连接和中间块输出。主 U-Net 的上采样路径继续去噪，最后用 VAE 解码视频。实体图、高斯图在这一步采用卷积与加法注入。[论文式（2）、图 4](https://arxiv.org/html/2403.07420v3#S3.SS3) · [控制分支](https://github.com/showlab/DragAnything/blob/main/models/DragAnything.py#L595) · [主 U-Net 注入位置](https://github.com/showlab/DragAnything/blob/main/models/unet_spatio_temporal_condition_controlnet.py#L450)

## 4. 训练

论文给出一套 ControlNet 式训练流程：主 SVD 作为冻结基座，新增条件编码器和控制分支可训练。公开实现可从预训练 SVD U-Net 复制输入卷积、扩散时间嵌入、下采样块和中间块。残差输出卷积零初始化，使新增分支在训练起点的加性残差为零。完整训练参数清单与损失实现无法从推理代码确认。[论文图 4](https://arxiv.org/html/2403.07420v3#S3.SS2) · [权重复制实现](https://github.com/showlab/DragAnything/blob/main/models/DragAnything.py#L677)

将论文式（3）按空间位置展开，忽略未报告的掩码重采样与归约细节：

$$
\mathcal L \propto
\sum_{i,u} M_i(u)\left\|\epsilon_i(u)
-\epsilon_\theta(z_t,t;\hat E,G,\text{首帧条件})_i(u)\right\|_2^2 .
$$

$u$ 是损失网格的空间位置，$M_i(u)$ 是对齐到该网格的逐帧实体掩码，$\epsilon_i$ 是论文使用的目标噪声记号，$\epsilon_\theta$ 是条件去噪预测。三帧示例中，控制图从固定云朵向量和跟踪点得来，损失掩码则来自真实视频里云朵逐帧的位置。掩码限制直接计入误差的位置，网络的跨帧与跨空间交互仍可能改变掩码外的画面。论文式（3）是简式，具体 SVD 预条件无法仅据此确认。[论文 §3.4、式（3）](https://arxiv.org/html/2403.07420v3#S3.SS4)

## 5. 推理

用户给一张首帧，通过 SAM 点击选中云朵，再拖拽区域内的点。公开交互程序将控制点插值为逐帧路径。若前三帧正好经过示例中的三个位置，两张条件图仍按同样规则生成。训练用的未来帧跟踪由用户轨迹替代，逐帧监督掩码也只在训练时使用。公开单视频示例可以直接读取掩码和轨迹文件。Co-Tracker 用于构造训练轨迹或做评测与可视化，交互生成调用直接接收用户轨迹。输出为 RGB 视频。[论文 §3.4](https://arxiv.org/html/2403.07420v3#S3.SS4) · [交互入口](https://github.com/showlab/DragAnything/blob/main/gradio_run.py#L359)

| 口径 | 设置 |
| --- | --- |
| 论文评测 | VIPSeg 验证数据统一为 14 帧、256×256 像素。论文未报告具体采样步数、引导强度，或 14 帧的选取方式。 |
| 公开单视频演示 | 示例调用为 20 帧、320×576 像素。推理管线默认 25 个去噪步，分类器无关引导（CFG）的系数沿视频帧从 1.0 线性增至 3.0，示例调用的控制残差缩放系数为 1.0。 |
| 公开代码的额外时间条件 | 去噪前代码将额外条件向量重写为 $[6,128,0.02]$，依次为帧率编码、运动等级编号、首帧噪声增强强度。这是去噪器实际收到的向量，与入口参数分开记录。 |

全图或背景拖拽可以引导画面产生平移、缩放等运镜效果。分类时可记为**二维轨迹条件，可间接引导运镜**，模型条件接口没有独立相机内外参或物体三维轨迹输入。[论文 §4.1、§4.4](https://arxiv.org/html/2403.07420v3#S4.SS4) · [单视频示例](https://github.com/showlab/DragAnything/blob/main/demo.py#L464) · [采样默认设置](https://github.com/showlab/DragAnything/blob/main/pipeline/pipeline_svd_DragAnything.py#L330) · [额外条件重写](https://github.com/showlab/DragAnything/blob/main/pipeline/pipeline_svd_DragAnything.py#L524)

## 6. 核心对比实验

**表 1 对比的是同类 SVD 基座下的两套运动控制系统。** VIPSeg 验证集以单张首帧为起点，参考轨迹由 Co-Tracker 从真实视频中提取。DragAnything 还使用实体掩码构造条件。论文未报告两种方法是否获得完全等量的区域提示、实际纳入评分的样本数，也未按遮挡或运动幅度分组报告结果。相同类型的基座有助于比较整套系统，条件图各自的贡献要看消融。DragAnything 相比 DragNUWA，在 ObjMC↓、FID↓ 和 FVD↓ 上均有改善。[论文 §4.1–4.2、表 1](https://arxiv.org/html/2403.07420v3#S4.SS2)

| 指标 | 衡量内容 |
| --- | --- |
| ObjMC↓ | 预测与参考锚点的二维欧氏距离。公开脚本把匹配到的轨迹逐点距离取均值，单位随坐标输入，代码未自行归一化到 256×256。该指标衡量锚点跟随。 |
| FID↓、FVD↓ | 分别衡量真实与生成样本的图像和视频特征分布距离，无物理单位。 |
| 人工偏好↑ | 用 30 张带掩码和轨迹的网络图像，由 3 位评审评估运动匹配与画面质量。两项都更偏好 DragAnything，运动匹配的优势更明显。 |

图 3 和图 7 能看到部分样例中的局部变形、背景误动与运镜偏离。它们与 ObjMC 互为补充。论文的定量协议没有独立测量目标上多个点的运动一致性或相机运动误差。[论文图 3、图 7–8](https://arxiv.org/html/2403.07420v3#S4.SS2) · [ObjMC 公开脚本](https://github.com/showlab/DragAnything/blob/main/utils/Eval_ObjMC/ObjMC.py)

## 7. 消融实验

| 对照 | 结果及其支持的判断 |
| --- | --- |
| 表 2：两种控制图全关、分别开启、同时开启 | 作者保持其他条件一致。单开任一路都改善 ObjMC↓，单开实体图的改善比单开高斯图更明显，两路同时开启的 ObjMC↓ 最好。仅实体图的 FVD↓ 略优于完整模型。这组结果支持两种条件都帮助锚点跟随。 |
| 表 3：全图计算去噪误差，或用逐帧实体掩码选取位置 | 加掩码后 ObjMC↓ 小幅改善，FID↓ 和 FVD↓ 也降低。这说明对目标区域施加监督在该设置下有收益。论文没有单独测出背景误动减少了多少。 |

**证据缺口。** 实体图同时带来图像扩散特征、跨帧稳定的实体标识和圆形覆盖。表 2 没有做同覆盖下的对照，即比较“掩码内的图像特征”和“跨帧一致但与图像无关的标识”。因此，实验支持实体图整体有效，图像语义单独贡献多少仍待确认。若要验证整个实体是否协调运动，可在预期为刚性平移的样例中测量同一实体上多个点的位移一致性及非目标区域误动。附录还给出了大幅运动会出现形变和画质退化的案例，精确三维旋转也超出了该二维条件的直接控制范围。[论文表 2–3](https://arxiv.org/html/2403.07420v3#S4.SS3) · [附录 §6.2](https://arxiv.org/html/2403.07420v3#S6.SS2)

## 8. 结论与可迁移设计

1. **让实体身份与逐帧位置各有自己的表示。** 这是作者的主要设计。固定区域特征向量提供跨帧实体线索，高斯图提供逐帧定位，表 2 支持两路均改善锚点跟随。首帧严重遮挡、目标大幅变形或多个实体高度相似时，单个首帧平均向量能保留的信息有限。
2. **先让条件与生成特征对齐，再选择注入算子。** 这是从方法提炼的设计思路。时间和空间位置先对齐后，简单的逐元素相加就能把条件送入控制分支。论文验证的是整套系统，注入尺度或位置各自的贡献未被隔离。小目标、密集轨迹、下采样碰撞都会影响这个做法。
3. **把监督范围与要改善的行为对齐，并为可能的副作用设独立指标。** 作者用实体掩码限制损失，消融显示在该设置下带来收益。根据评测设计进一步推断，若任务还要求固定背景、保持物体外观或解耦相机，就应给这些能力各自设置度量。掩码质量也是这一策略的前提。

**RayLift 最小验证。** 检验“首帧掩码池化特征是否比稳定实体标识更能帮助视频分支找到正确目标”。保持轨迹、现有 slot 编码、注入路径、训练预算一致，只替换实体特征来源：一组采用首帧掩码池化向量，一组在相同位置使用同维、与图像内容无关且跨帧稳定的实体向量。用同一组双物体输入和种子评测，选外观相似的物体交叉运动，或固定物体运动但改变相机轨迹的情形。分别看目标关联错误、锚点误差和背景误动。如果困难样例中两组表现接近，就暂时放下“额外图像语义是主要收益来源”的解释，继续排查轨迹表示与注入路径。
